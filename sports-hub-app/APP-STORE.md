# رفع Sports Hub على TestFlight ثم App Store (DW-077)

> **الحالة:** تجهيز فقط. لا نشر عام ولا تاريخ إطلاق إلى أن يقول المالك. الطريق: **TestFlight أولاً**.

## 0. ما لازم يكون جاهزاً (يسويه المالك)
| البند | التفاصيل |
|---|---|
| حساب **Apple Developer** المدفوع | 99 دولار/سنة، من developer.apple.com/programs. الحساب المجاني ما يرفع على TestFlight ولا App Store |
| **Bundle ID** فريد | الحالي للتجربة `app.sportshub.trial`؛ سجّل واحداً بحسابك (مثل `com.اسمك.sportshub`) في Certificates, Identifiers & Profiles |
| **اسم التطبيق** | «Sports Hub» قد يكون محجوزاً عند Apple. بدائل: «Sports Hub — إدارة النادي» أو «Sports Hub BH». يظهر الاسم المتاح عند إنشاء التطبيق |
| **سياسة خصوصية برابط عام** | التطبيق فيه صفحة `/privacy`؛ لازم تنشر نسخة الويب برابط ثابت (Vercel) وتحط الرابط في App Store Connect |
| **اتصال Supabase الحقيقي** | نسخة بيانات خيالية بس لا تكفي للنشر العام (انظر 5). لـ TestFlight مع إداريين حقيقيين نحتاج `VITE_SUPABASE_*` و`VITE_PRIVACY_CONTACT` |
| مراجعة المحامي للـDPA | قبل أي بيانات لاعبين حقيقية |

## 1. جهّز المشروع (على الماك)
```bash
cd ~/claude/sports-hub-app && git pull
# لبناء بالمفاتيح الحقيقية ضعها قبل ios:sync (انظر DEPLOY-TRIAL.md):
#   VITE_SUPABASE_URL=... VITE_SUPABASE_ANON_KEY=... VITE_PRIVACY_CONTACT=... npm run ios:sync
npm run ios:sync && npm run ios:open
```
في Xcode، الهدف **App** ← General:
- **Display Name:** الاسم النهائي. **Bundle Identifier:** اللي سجّلته.
- **Version** `0.1.0` و**Build** `1` (ارفع Build مع كل رفع).
- Signing: *Automatically manage signing* مع الـTeam المدفوع.
- الأيقونة (1024) والـsplash جاهزان في المشروع (من `brand/store-1024.png`).

## 2. أنشئ التطبيق في App Store Connect
appstoreconnect.apple.com ← Apps ← **+** ← New App: المنصة iOS، الاسم، اللغة الأساسية **العربية**، Bundle ID، SKU (أي نص فريد، مثل `sportshub-1`).

## 3. ارفع الـBuild
Xcode: اختر جهاز **Any iOS Device (arm64)** ← **Product ← Archive** ← Organizer ← **Distribute App ← App Store Connect ← Upload**. بعد دقائق يظهر في TestFlight (حالة Processing ثم جاهز).

## 4. TestFlight
- **Internal Testing** (حتى 100، لازم يكونون أعضاء في حسابك بـApp Store Connect): بدون مراجعة آبل.
- **External Testing** (حتى 10,000 برابط أو إيميل): أول Build يخضع لـ**Beta App Review** (عادةً يوم إلى يومين). عبّي «What to Test» ووصف الاتصال.
- أضف إيميلات الإداريين، يوصلهم تطبيق **TestFlight** ويثبّتون منه.
- يوم الاختبار: أضف في «What to Test» صراحة: «نسخة تجريبية ببيانات خيالية» أو «ببيانات ناديك».

## 5. قبل النشر العام (لا نبدأه الحين)
- **App Privacy** (جدول أدناه) وسياسة خصوصية برابط عام.
- **حساب تجريبي لمراجعة آبل** (Demo account): ينفع «دخول تجريبي» بدور إدارة النادي (وضع العرض).
- التطبيق يجب أن **يعمل ويفيد** بدون شرح خارجي. آبل ترفض التطبيقات «التجريبية/الناقصة» (Guideline 2.1 و4.2). نسخة عرض بيانات خيالية فقط غالباً ترفض؛ نحتاج حسابات حقيقية أو وصفاً واضحاً.
- **حذف الحساب داخل التطبيق** مطلوب لأي تطبيق فيه إنشاء حساب (Guideline 5.1.1): موجود «احذف بياناتي»؛ تأكد أنه يمسح حساب Supabase وليس المحلي فقط.
- **Sign in with Apple** مطلوب إذا فعّلنا Google. عندنا الاثنان خلف علامات `VITE_AUTH_*`؛ فعّلهما معاً أو أطفئهما.
- التصنيف العمري: لا محتوى حساس، غالباً 4+.

## 6. نصوص المتجر (مسودة، لا وعود ميزات غير موجودة)
**الاسم:** Sports Hub  ·  **العنوان الفرعي (≤30):** إدارة النادي · نسخة تجريبية

**الوصف (عربي):**
> أداة لإدارة النادي الرياضي: تشكيلة المباراة، الحضور والغياب، وملف اللاعب. تعدّ بطاقة المباراة كصورة لقروب الفريق.
> • تشكيلة المباراة: اختيار الأساسيين والبدلاء ومسودة مقترحة يقرر فيها المدرب.
> • الحضور والغياب: تسجيل بلمسة، نسبة الفريق، وملخص للأسماء.
> • إضافة اللاعبين: لصق قائمة أو لاعب لاعب.
> • بطاقة المباراة: صورة بالشعار والخصم والتاريخ والزي، جاهزة للمشاركة.
> نسخة تجريبية قيد التطوير. البيانات المعروضة في وضع التجربة خيالية.

## 7. App Privacy (ما نجمعه عند تفعيل Supabase)
| البيانات | تُربط بالمستخدم؟ | تُستخدم للتتبع؟ | الغرض |
|---|---|---|---|
| الاسم والإيميل (حساب الإداري) | نعم | لا | وظائف التطبيق، المصادقة |
| معرّف المستخدم | نعم | لا | وظائف التطبيق |
| بيانات اللاعبين (اسم، رقم، مركز، حضور، تقييم المدرب) يدخلها النادي | نعم (بحساب النادي) | لا | وظائف التطبيق |
| بيانات صحية/لياقة (حمل التمرين) إن فُعّلت | نعم | لا | وظائف التطبيق؛ **لا نفعّلها قبل DPA وموافقة** |
| بيانات الاستخدام/التحليلات | — | — | لا نجمع (لا SDK تتبع) |
| لا تتبّع عبر التطبيقات والمواقع | — | — | App Tracking Transparency غير مطلوب |
> هذا الجدول مسودة من واقع الكود؛ راجعه مع المحامي قبل التعبئة. في وضع التجربة بدون Supabase لا تُرسل بيانات خارج الجهاز.

## 8. معلومات للتأكد منها بنفسك
