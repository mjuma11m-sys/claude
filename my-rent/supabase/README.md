# مزامنة إداراتي بين أجهزة العائلة (DW-018)

المزامنة **مطفية** لين تسوي الخطوات تحت. قبلها كل البيانات على الجهاز بس، وما يطلع أي طلب لـ Supabase.

## الخطوات (مرة وحدة، تقريباً 10 دقايق)

| # | وين | شنو تسوي |
|---|---|---|
| 1 | supabase.com ← New project | سوّ مشروع جديد (الخطة المجانية تكفي). اختار المنطقة الأقرب للبحرين من القائمة المتوفرة |
| 2 | SQL Editor | الصق محتوى `migrations/20261015000000_family_sync.sql` كامل واضغط Run |
| 3 | Authentication ← Providers | تأكد إن **Email** مفعّل |
| 4 | Authentication ← URL Configuration | **Site URL** = رابط التطبيق (مثلاً رابط Vercel)، وأضفه بـ **Redirect URLs** |
| 5 | Authentication ← Email Templates ← Magic Link | (اختياري، ينصح فيه للآيفون) أضف سطر: `الكود: {{ .Token }}` — عشان لو الرابط فتح بمتصفح ثاني، تكتب الكود بالتطبيق |
| 6 | Project Settings ← API | انسخ **Project URL** و **anon public** (أو publishable). **لا تنسخ service_role أبداً** — التطبيق يرفضه |
| 7 | التطبيق ← الإعدادات ← المزامنة | الصق الرابط والمفتاح، أشّر على الموافقة، احفظ، وسجّل دخول بإيميلك |
| 8 | نفس المكان | «أنشئ العائلة وارفع البيانات» — بيانات جهازك تصير بداية سجل العائلة |
| 9 | «كود دعوة لجهاز ثاني» | أرسل الكود للوالد بالواتساب. يسوي الخطوة 7 على جواله (نفس الرابط والمفتاح، وإيميله هو) ويكتب الكود |

## شلون تشتغل

- كل تعديل (دفعة، مصروف، تراجع…) صف واحد بجدول `events`. كل جهاز يعيد تطبيقها بالترتيب، فما فيه تعارض بين جهازين.
- **RLS:** العضو يقرأ ويضيف أحداث عائلته بس. ما فيه تعديل ولا حذف لأي حدث. غير الأعضاء يشوفون صفر.
- بدون نت: التطبيق يشتغل عادي، والتعديلات تنتظر بطابور وتنرفع لما يرجع النت (بدون تكرار).
- «احذف كل البيانات» بالإعدادات يمسح **الجهاز بس**. حذف بيانات العائلة من السيرفر زر منفصل للمالك.

## الاختبارات

```bash
npm run test:sync                                        # محرّك المزامنة بسيرفر وهمي (19 فحص)
PGHOST=… PGPORT=… PGUSER=postgres npm run test:db        # الـ migration + RLS على Postgres محلي (18 فحص)
```
