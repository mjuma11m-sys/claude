# DW-011 · إداراتي: واجهات التطبيق كاملة بالهوية والحركات

- **الأولوية:** P1 · **المسؤول:** CEO · **فُتحت:** 2026-10-13

## الموجز (CEO)
- **الهدف:** واجهات التطبيق كاملة (8 أقسام) بالهوية الجديدة والحركات، تشتغل فعلياً.
- **الافتراض:** كود My-rent الأصلي مو بالريبو ← نبني الواجهات في `my-rent/` ببيانات تجريبية، والربط بـ Supabase يصير بتبديل ملف واحد.
- **النجاح:** 8 شاشات بدون أخطاء على 390/820/1280 · تسجيل دفعة بأقل من 3 ضغطات · كل اختبار ✅.
- **الأقسام:** CPO، Design، CTO، Legal، QA، COO.

## تقارير الأقسام
- 📦 CPO: Must: الرئيسية، المستأجرين + تسجيل دفعة، الميزانية + مصروف، بنك العائلة. Should: المحفظة/السفر/المنزل/الموردين كقوائم. Won't (الحين): تسجيل دخول وSupabase.
- 🎨 Design: الرئيسية = بطاقة التحصيل + «يحتاج انتباهك» + مربعين (المصروف، البنك). البطاقة تفتح نافذة الوحدة وفيها الدفع. الخاتم شفاف بخلفية بطاقة التحصيل.
- 💻 CTO: Vite + React 18 + TS strict، بدون router (hash)، useReducer + localStorage خلف `useStore()`. 56KB gzip.
- ⚖️ Legal: الأسماء والأرقام وهمية + «* بيانات تجريبية» بكل شاشة. أول ما تدخل بيانات حقيقية: RLS + auth (قرار DW-008).
- ⚙️ COO: الشغل بترتيب: data → kit → pages → اختبار → نشر تجريبي.

### التنسيق
- 🔍 QA ← 💻 CTO: تسجيل دفعة بالغلط بدون رجعة؟ ← رسالة فيها «تراجع» 5 ثواني ✅.
- 🎨 Design ← 📦 CPO: CPO طلب رسوم بيانية بالرئيسية؛ Design: رقم واحد كبير + شريط أوضح بالجوال ✅.
- 💻 CTO ← 🎨 Design: النافذة من تحت بالجوال، وبالوسط بالكمبيوتر (نفس المكوّن) ✅.
- 🔍 QA: المبلغ يقبل الأرقام العربية (١٨٠) والفاصلة، ويرفض الصفر والحروف.
