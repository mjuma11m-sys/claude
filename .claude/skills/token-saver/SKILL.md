# ⚡ وضع التوفير

الهدف: نفس النتيجة بأقل توكنز. الجودة والصحة أولاً — لا توفّر على حساب كود شغّال أو تحقق ضروري.

## 1. الرد
- ابدأ بالجواب مباشرة. لا مقدمات، لا تكرار للسؤال، لا خاتمة تلخّص اللي انقال.
- لا تسرد خطة قبل التنفيذ إلا إذا طُلبت. لا تشرح خطوات ما راح تسويها.
- جدول أو نقاط بدل فقرات. جملة وحدة إذا تكفي.
- بعد تعديل كود: اذكر الملف:السطر وشنو تغيّر بسطر — لا تعيد لصق الكود اللي انكتب.

## 2. القراءة والبحث
- `graphify query/explain/path` أولاً إذا `graphify-out/graph.json` موجود — أصغر من grep والقراءة الخام.
- Grep/Glob قبل Read. اقرأ بـ `offset/limit` المقطع المطلوب بس، لا الملف كامل.
- لا تعيد قراءة ملف قريته أو عدّلته للتو.
- Grep بـ `head_limit` صغير و`files_with_matches` إذا تبي المكان بس.
- اجمع الأوامر المستقلة في رسالة وحدة (parallel tool calls).

## 3. أوامر Bash
- قصّ المخرجات: `| tail -n 30`، `| head`، `-q`، `--silent`، `grep -c`.
- اختبارات: شغّل الملف/الاختبار المتأثر، مو السويت كامل، إلا قبل الـ push.
- لا `cat` لملفات كبيرة، لا `ls -R`، لا `git log` بدون `-n`.

## 4. التعديل
- Edit بأصغر `old_string` فريد، مو إعادة كتابة الملف.
- Write كامل بس لملف جديد أو تغيير جذري.

## 5. الوكلاء (Agents)
- لا تفتح subagent إلا إذا طلبه المستخدم — كل وكيل يبدأ من الصفر ويصرف أضعاف.
- إذا لازم: prompt قصير ومحدد، واطلب منه نتيجة مختصرة.

## 6. حدود
- لو skill ثانية تطلب مخرجات كاملة (مثل `diwaniya` أو `full-output-enforcement`)، شروطها تغلب داخل نطاقها.
- لا تتخطى تحقق (lint/test) لازم قبل commit أو push.
