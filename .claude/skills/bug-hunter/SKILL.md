# 🐞 Bug Hunter

**ممنوع التخمين.** لا تعدّل كود قبل ما يكون عندك سبب مثبت بدليل.

## 1. اجمع (بدون تعديل)
- رسالة الخطأ كاملة + stack trace + وين يطلع (متصفح/سيرفر/build/DB).
- آخر شي تغيّر: `git log -n 5 --oneline` و `git diff`.
- البيئة: محلي أو إنتاج؟ يصير دايماً أو أحياناً؟

## 2. كرّر
- اكتب أصغر خطوات/أمر/test يطلع الخطأ. لو ما تكرر ← اجمع logs أكثر، لا تصلح.

## 3. ضيّق
- اتبع الـ stack من أعمق سطر في كود المشروع (مو المكتبات).
- افرض فرضية وحدة ← اختبرها بـ log/print/query واحد ← أكّد أو ارفض. سجّل الفرضيات المرفوضة بسطر.
- طبقات الفحص بالترتيب: input → network (status, payload) → backend → DB/RLS → response → render.

| العرض | شيّك أول |
|---|---|
| `undefined` / `null` | شكل البيانات الراجعة فعلياً (log الـ response) |
| بيانات فاضية بدون خطأ | RLS policy أو filter |
| يشتغل محلي مو إنتاج | env vars، CORS، build، اختلاف نسخ |
| أحياناً بس | race condition، cache، timezone، بيانات حدّية |
| بعد تحديث مكتبة | changelog / breaking changes |

## 4. صلّح
- أصغر تعديل يعالج **السبب** مو العرض (لا `try/except: pass`، لا `?.` لإخفاء null بدون فهم).
- لو السبب في أكثر من مكان، صلّح الكل.

## 5. أثبت
- الخطوات من 2 تمر الحين · أضف test يفشل قبل الإصلاح وينجح بعده · شغّل tests الملف/الميزة.

## الرد
```
السبب: <جملة + file:line>
الدليل: <log/output اللي أثبته>
الإصلاح: <شنو تغيّر>
التحقق: <test/أمر نجح>
```
لو فشل إصلاحين: وقّف، ارجع للخطوة 1، واعرض الفرضيات المرفوضة.
